{{ include "bazarr.fullname" . }} runs one Bazarr (StatefulSet, downtime on every upgrade).
{{- if not (dig "auth" "type" "" .Values.config) }}

config.auth.type is unset: Bazarr has no login unless one is saved in its
settings, and its web UI shows the API key to whoever reaches it. Set a login
(config.auth or Settings > General) before exposing the Service.
{{- end }}
{{- if .Values.apiKey.existingSecret.name }}

The API key comes from the Secret {{ .Values.apiKey.existingSecret.name }} (key {{ .Values.apiKey.existingSecret.key }}), read at startup only:
roll the pod after changing it.

  kubectl -n {{ .Release.Namespace }} rollout restart statefulset/{{ include "bazarr.fullname" . }}
{{- end }}
{{- if .Values.externalDatabase.enabled }}

Bazarr uses PostgreSQL at {{ .Values.externalDatabase.host }}:{{ .Values.externalDatabase.port }}: the database {{ .Values.externalDatabase.database }}
must exist, owned by the login in the Secret {{ .Values.externalDatabase.existingSecret.name }}. A missing database makes the pod
crash-loop.
{{- end }}

Web UI:
{{- $path := default "/" (include "bazarr.urlPath" .) }}
{{- if .Values.ingress.enabled }}
{{- range .Values.ingress.hosts }}
  https://{{ . }}{{ $path }}
{{- end }}
{{- end }}
{{- if .Values.httpRoute.enabled }}
{{- range .Values.httpRoute.hostnames }}
  https://{{ . }}{{ $path }}
{{- end }}
{{- end }}
  kubectl -n {{ .Release.Namespace }} port-forward service/{{ include "bazarr.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  then open http://127.0.0.1:{{ .Values.service.port }}{{ $path }}
{{- if not .Values.hostUsers }}

hostUsers is false: the pod runs in a user namespace. Nodes without support
(containerd 2.0+ or CRI-O, runc 1.2+, kernel 6.3+) or volumes without idmapped
mounts (NFS/SMB) cannot start it; set hostUsers=true to use host users.
{{- end }}
